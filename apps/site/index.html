Why Nocap Cloud

The deploy experience of a big platform, on a small server you own.

01 / Light

Three containers. That's it.

Panel, API and worker share one image. The job queue lives in Postgres, so there is no Redis. More memory stays free for your apps.

02 / Git first

GitHub and GitLab in a few clicks.

A GitHub App created for you from a manifest, or one GitLab token. Webhooks, deploy keys and commit status are set up automatically.

03 / Yours

Open source, no strings.

Apache 2.0, no account, no license key, no telemetry. Your code, secrets and data never leave your server.

Architecture

Simple enough to understand in one look.

Traefik takes the traffic and gets the certificates. Nocap builds and runs your apps as plain Docker containers next to it. Postgres keeps the panel data and the job queue.

How it works

From a clean server to a live app in three steps.

  1. 1

    Install with one command

    The installer checks the server, sets up Docker and starts the stack. Then you create your admin account in the browser.

  2. 2

    Connect GitHub or GitLab

    Pick the repository and branch. Nocap builds from your Dockerfile or Compose file, and detects the port for you.

  3. 3

    Push and it is live

    Each push deploys with HTTPS on your domain. Watch the logs live and roll back if something looks wrong.

FAQ

Questions

Something else? Ask in Discussions.

Is it really free? +

Yes. Nocap Cloud is open source under the Apache 2.0 license. There are no paid plans, no limits and no account to create. You only pay for your own server.

What server do I need? +

Ubuntu 22.04 or 24.04 on amd64 or arm64, with at least 1 GB of RAM (2 GB recommended, because builds need memory) and 20 GB of disk. Ports 80, 443 and 3000 must be free.

Can I use it in production today? +

Not yet. The project is in early development and deploys arrive in the next versions. Follow the roadmap or star the repository to hear about v0.1.

Does it send data anywhere? +

No. There is no telemetry and the panel loads no third-party scripts or fonts. The only outside call is a daily check for new releases on GitHub, starting in v0.1.

How is it different from Coolify or Dokploy? +

Same idea, written from scratch in TypeScript with a focus on a small footprint: three containers, no Redis, and one image for the whole panel.

How can I help? +

Vote on ideas, report bugs or send a pull request. The community page has the ideas board and a guide to your first contribution.
